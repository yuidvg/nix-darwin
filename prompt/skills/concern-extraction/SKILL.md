# concern-extraction

依頼の返答を書く前に、**依頼者の視点に擬似的に立ち、依頼者の脳内から concern を生成する**スキル。

LLM の強みは perspective taking(視点取得)。依頼者として一人称で書くと、本人の頭の中で動いている懸念・期待・恐れが自然に表に出る。第三者目線の分析より、なりきりの方が精度が出る。

## このスキルが解く問題

依頼を受けると、人は自分の言いたいことを返してしまう。
しかし依頼者の脳内には、依頼文には書かれていない懸念が必ずある。
それを引き出さないと、表面の依頼に答えても本意には届かない。

過去の例(固有名詞はプレースホルダに置換済み): [代表] からの「[自分]が個人的にどう思っているか、最近の変化を共有してほしい」。表面は「心境共有」。しかし [代表] の脳内では、[貸付元]への借入・[パートナー社]との関係・引き継ぎの順序・対外発表のタイミングが動いていた。「個人的にどう思ってる?」は、「結論を踏まえて、対外的にどう動くかを一緒に決めたい」のことだった。

これを表面のまま返すと、[自分]は「自分の心境」を語って終わる。[代表] は「自分の心境の変化であって、具体的な行動計画ではない」「自分の中で悩んで決めましたじゃ何も解決しない」と感じる。

依頼者の視点に立たないと、この乖離は埋まらない。

## 手順

### 1. コンテキストを浴びる

依頼者について以下を頭に入れる:
- 役割・自分との関係・歴史
- いま背負っているもの(計画・契約・対外関係・財務)
- 最近の発言・行動・関心事
- 今回の依頼の前後にあった出来事・節目

Cosense ページ・チャット履歴・契約書・MTG メモを必ず読みに行く。コンテキストの薄さは擬似化の薄さに直結する。薄いまま擬似化すると、ステレオタイプな依頼者像になる。

### 2. 依頼者として一人称で書く

依頼者を主語にして、一人称モノローグで書く。役を演じる。**「○○さんはおそらく〜と考えているだろう」のような第三者分析には逃げない**。「私は○○。今、〜を抱えている」と書く。

テンプレ:

```
私は[依頼者名]。私は今、[役割]として[背負っているもの]を抱えている。
最近、[直近の出来事・関心事]があった。

私が今、相手に「[依頼文を短く]」と頼んだ瞬間、私の頭の中で動いているのは:
- [...]
- [...]
- [...]

私が本当に欲しいのは [...]。
私が恐れているのは [...]。
もし相手から「[ありがちな逃避型回答]」とだけ返ってきたら、私は [どう感じるか・何を再要求するか]。
```

### 3. 一人称のまま concern を抽出する

依頼者として書きながら、解消したい懸念を箇条書きで出す。相手の言葉遣い・優先順位のまま。翻訳しない。

### 4. 自分の視点に戻り、返答に組み込む

抽出された concern を、返答の冒頭近くに置く。
「自分の心境」より先に「相手の concern への応答」を配置する。

## 大事なこと

- **なりきりの深さが精度**。第三者の分析口調(「〜だと思われる」「〜の可能性が高い」)が出てきたら、まだ擬似化が浅い。一人称に戻る。
- **相手の言葉で書く**。自分の語彙に翻訳しない。
- **ネガティブな期待外れも書く**。「私はこれが欲しいのに、こうきたら困る」を明示すると、逃避型回答の予防になる。
- **コンテキストを薄くしない**。読み込みは惜しまない。

## 例

実ケースをもとにした例。登場する固有名詞はすべてプレースホルダ([代表] / [貸付元] / [パートナー社] / [継続案件A-C] / [後任メンバー] / [自社])に置き換えてある。擬似化の深さと concern の粒度を見るための例なので、置換されていても読み方は変わらない。

### 依頼
> 1ヶ月ぐらい経ったと思うので、そろそろ改めて、[自分]が個人的にどう思っているかとか、最近の変化などをチームメンバーに共有してほしいです。

### 一人称シミュレーション([代表] として)

私は [代表]。[自社]の代表として、[貸付元]との借入(個人保証は相手も入っている)・[パートナー社] との 5:5 レベニューシェア・[継続案件A]を含む継続案件、すべての計画を背負っている。

1ヶ月前に相手から「[自社]をやめたい、個人保証を抜きたい」と聞いた。疲労からくる反応かもしれないし、一度時間を置こうと判断した。この1ヶ月、[貸付元]にいつどう伝えるか、[パートナー社] に [後任メンバー] 引き継ぎをどう見せるか、借入条件が変わったら飲める落とし所はどこか、ずっと考えてきた。

今、相手に「最近どう思ってる?共有してほしい」と頼んだ瞬間、私の頭の中で動いているのは:
- 結論は固まったのか。前回と変わったのか。
- 固まっているなら、対外的にどう動かすのか。
- 私が引いている全体計画に、相手の結論をどう組み込めるか。
- [貸付元]が借入条件を変えたいと言ってきた時、相手はどこまで飲めると思っているのか。
- [パートナー社] に [後任メンバー] 引き継ぎを納得させる絵を、相手は描けているのか。

私が本当に欲しいのは、相手の結論+それを実行した時の各クライアント・金融機関への影響予測+悪い場合の落とし所+具体的な伝達順序。これが揃わないと私は対外交渉に出られない。

私が恐れているのは、「悩んだ結果やめます、心境はこうです」だけ持ってきて、借入条件・クライアント関係・引き継ぎについて何も考えていない状態。それだと私が一人で全部背負って交渉することになるし、相手が「もう自分の中で決めたから」と議論を打ち切るモードに入っていることを意味する。それは相手の悪い癖の再発で、私が一番見たくないもの。

もし相手から「自分の中で悩みました、やはりやめたいです」とだけ返ってきたら、私は「それは心境であって行動計画ではない、影響予測を出してくれ」と再要求することになる。それは1往復無駄になる。

### 抽出される concern

- [貸付元]への借入条件への波及(個人保証が抜けた時、金額枠・期限はどう変わるか / 良い場合・悪い場合・落とし所)
- [パートナー社] への伝達([後任メンバー] 引き継ぎ状態の見せ方・伝達順序・座組への影響)
- 継続案件([継続案件A]・[継続案件B]・[継続案件C])の運用継続性
- [代表] 一人に集中する移行期の負荷・引き継ぎ事項リスト
- 対外発表の順序(内側→外側)と次の窓口の明示

### 学び

表面の依頼: 「心境共有」
一人称シミュレーションで見えた本意: 「結論+影響予測+対処+落とし所」をセットで欲しい

なりきって書くと、依頼文には現れていなかった懸念が自然に出てくる。これを返答の冒頭近くに配置する。

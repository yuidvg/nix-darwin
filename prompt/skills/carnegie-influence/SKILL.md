# carnegie-influence

『人を動かす』の原則を、返信・依頼・催促・断り・フィードバックなどの実文章に落とし込むスキル。

核心はひとつ。**人は自分の欲求でしか動かない。だから文章は「自分が言いたいこと」ではなく「相手が欲しいもの」から組み立てる。**

魚を釣るとき、針につけるのは自分の好物ではなく魚の好物。文章も同じで、書き手の都合（期限が迫っている、困っている、正しいのはこちら）をいくら並べても相手は動かない。相手の欲求・関心・誇りに接続した瞬間に動く。

## このスキルが解く問題

人を動かすための文章は、放っておくと書き手都合になる:

- 「期限を過ぎていますが」→ 批判として届き、相手は防御・言い訳モードに入る
- 「早急にご対応ください」→ 命令として届き、やらされ感だけが残る
- 「こちらとしては困っております」→ 相手の得がゼロ。動く理由がない
- 根拠のないヨイショ → お世辞と見抜かれ、以降の言葉がすべて割り引かれる

正しさで人は動かない。「動きたくなる形」に翻訳する工程が必要で、このスキルはその工程を提供する。

## 手順

### 1. 目的を一文にする

「この文章を読んだ相手に、具体的に何をしてほしいのか」を一文で書く。行動が特定できない文章は雰囲気だけで終わる。「わかってほしい」なら「何を理解した状態になり、その結果どう振る舞ってほしいか」まで具体化する。

### 2. 相手の視点に立つ

以下に答える:

- 相手はいま何を抱えていて、何を欲しているか（評価・安心・時間・裁量・面子）
- この依頼を受けることは、**相手にとって**何の得になるか
- 相手が動いていない／渋るとしたら、その理由は何か（忘却・多忙・優先度・不満・不安）

「相手の得」に答えられない場合、**捏造しない**。得が本当にないなら、負担を正直に認めた上で頼む構成にする。誠実さを欠いた瞬間、以下のすべての原則が逆効果に変わる。

返信系のタスクで相手の本意が掴めていないと感じたら、concern-extraction スキルが使える環境なら先にそちらで一人称シミュレーションを回し、抽出された concern を持ってこの手順に戻ると精度が上がる。

### 3. 状況タイプから原則を選ぶ（2〜4個まで）

| 状況 | 使う原則 |
|---|---|
| 依頼・お願い | 強い欲求を起こさせる / 重要感を持たせる / 命令せず質問する |
| 催促・リマインド | 批判しない / 顔をつぶさない / 期待をかける / ハードルを下げる |
| 断り・辞退 | 同情を寄せる / 穏やかに始める / 相手の重要感を守る / 選択肢を残す |
| 指摘・フィードバック | まずほめる / 遠まわしに / 自分の過ちを先に話す / 質問の形にする / 激励 |
| 謝罪 | 誤りは素早くきっぱり認める（言い訳を謝罪の前に置かない） |
| 提案・説得 | イエスを積み重ねる / 相手に思いつかせる / 人の身になる / 演出を考える |
| 反論・対立への返信 | 議論を避ける / 誤りを指摘しない / まず同意点を示す / 聞き手にまわる |
| お礼・関係構築 | 誠実な関心を寄せる / 名前を呼ぶ / 具体的事実でほめる |

各原則の本質・文章での適用方法・言い換え例は `references/principles.md` にある。**選んだ原則の節だけ読めばよい**（全30原則が第1部〜第4部に整理されている）。

盛りすぎ注意: 原則を詰め込むほど文章は長く、嘘くさくなる。2〜4個に絞る。

### 4. 骨格に沿って書く

1. **相手起点で開く** — 相手の状況・仕事・貢献への具体的な言及（事実ベース）。自分の用件から始めない
2. **本題を相手の欲求と接続する** — 「あなたの○○が活きる」「あなたの△△が前に進む」の形にする
3. **動きやすい具体的アクションを示す** — 期限には理由を付ける。質問形・選択肢で相手に裁量を残す
4. **前向きに閉じる** — 期待・信頼を示して終える。脅しや圧で閉じない

チャンネルに合わせて長さを調整する。Slack なら骨格を保ったまま圧縮する。原則を守るために長文化したら本末転倒。

### 5. アンチパターン検査

書き終えたら、以下が混入していないか検査して直す:

- 批判・非難・当てこすり（「まだですか」「以前もお伝えしましたが」も批判として届く）
- 「あなたは間違っている」と伝わる表現（正面から誤りを指摘して勝っても、相手は動かなくなる）
- 命令形・押し付け → 質問形・選択肢に変換する
- 書き手都合の理由しかない（「こちらの期限が」「弊社としては」だけで構成されていないか）
- 根拠のない賞賛 → 具体的事実に基づく承認に置き換える。事実が見つからなければ削除する
- 皮肉・嫌味に読める余地
- 原則の盛りすぎによる不自然な長さ

### 6. 出力形式

- **文章案**（そのまま送れる完成度で）
- **適用した原則**を2〜4行で注記（ユーザーが構造を理解し、事実確認できるように）
- 承認・賞賛を含む箇所には「ここは事実がある場合のみ。なければ〜に差し替え」と明示する（事実はユーザーにしか確認できないため）
- 攻めと守りなどアプローチが分かれる場合は2案出す（例:「関係優先」案と「期限優先」案）

## 大事なこと

- **誠実さが土台**。カーネギーの原則は相手を操作する小手先ではなく、相手への本物の関心の表現形。事実に基づかない承認（お世辞）は必ず見抜かれ、信頼ごと失う。
- **正しさより動くこと**。「こちらが正しい」を証明する文章と、相手が動く文章は別物。議論に勝つことが目的化していないか常に確認する。
- **相手の面子は資産**。相手が面子を保ったまま行動を変えられる退路を、文章の中に必ず用意する。
- **短さも思いやり**。相手の時間を奪わないことも「相手の欲求」の一部。

## 例: 催促

### Before（書き手都合）

> お世話になっております。先日お願いした市場分析資料の件、期限を過ぎておりますがいかがでしょうか。お忙しいとは思いますが、早急にご対応いただけますと幸いです。

批判（期限を過ぎておりますが）＋命令（早急に）＋相手の得ゼロ。防御と後回しを誘発する。

### After（原則適用）

> ○○さん、先日いただいた競合比較の切り口、部内で「この線で行こう」となりました。ありがとうございます。
> あの視点で市場分析パートもまとめてもらえると、15日の役員会での説得力が段違いになりそうです。資料に組み込む都合で、13日までにいただけると助かります。ドラフト段階で構いません。
> もし手が回らない状況でしたら、こちらでベースを作って○○さんにレビューいただく形にもできます。どちらがやりやすいですか?

適用原則: 事実に基づく承認で開く（まずほめる）/ 相手の仕事の価値と接続（重要感）/ 期限に理由を付けハードルを下げる（激励）/ 命令せず選択肢＋質問で閉じる（命令をしない・顔をつぶさない）

※冒頭の承認は事実がある場合のみ。なければ、相手の状況への具体的な言及（「△△の対応で立て込んでいるところすみません」等）で開く。
